# 密语软件新手操作与测试手册

这份手册按实际操作顺序解释软件，并说明每项测试能验证什么。第一次先在一台电脑上打开两个窗口，不需要准备第二台电脑，也不用先掌握椭圆曲线数学。

## 一 先分清软件里的几个东西

Alice 和 Bob 是通信双方的名称，相当于发送消息的两个人。双窗口演示把两个人都放在你的电脑上运行；两个窗口之间仍使用真正的 TCP 网络连接，不是把同一份消息直接复制到另一个窗口。

软件有三页：

| 页面 | 你在这里做什么 |
| --- | --- |
| 通信 | 发送文字、图片、视频和普通文件，查看接收情况 |
| 会话与身份 | 查看算法用途、对端身份指纹和当前会话标识 |
| 安全实验 | 查看密文日志，运行篡改与重放演示，导出实验日志 |

**身份保护口令**是启动时输入的密码，用来解开保存在自己电脑上的身份私钥。它不是直接拿来加密聊天内容的会话密钥，不会发给对方。软件没有预设默认密码；第一次由你设置，之后用相同口令解锁。

**公钥和私钥**是一对。公钥可以提供给别人，私钥由自己保管。别人用你的公钥加密的内容，要用你的私钥解开；你用私钥生成的数字签名，别人可以用你的公钥验证。具体加密与签名操作由密码库实现。

**会话密钥**是双方这次连接临时使用的秘密。程序会自动协商和派生，不需要你手工填写。重新连接会重新生成临时协商密钥。

**身份指纹**是对公钥计算出的摘要，方便双方核对“这是不是要联系的那个身份”。它不是密码，不需要保密。Alice 和 Bob 的本机指纹通常不同；要交叉核对，而不是要求两个人自己的指纹相同。

## 二 第一次启动

### 第一步 打开演示

进入项目所在文件夹：

```text
D:\Projects\securechat-sm2-sm4
```

以上路径仅为示例，请使用实际下载位置。首次使用先运行 `install.bat` 安装依赖，再找到 `start_demo.bat` 并双击。在隐藏扩展名的资源管理器中，它可能只显示为 `start_demo`，文件类型为 Windows 批处理文件。

第一次设置至少 8 个字符的身份保护口令，按提示再次确认。自己记好，软件没有找回旧口令的功能。以后启动时输入同一口令。

如果你取消口令输入，程序会退出，这是正常行为。若软件提示“身份解锁失败”，先检查输入法、大小写和口令是否输错，不要立即删除文件。

### 第二步 等待两个窗口出现

你会看到 Alice 和 Bob 两个窗口。演示启动时会自动让 Bob 监听、Alice 连接，并自动选择一个空闲端口。

这时先不要手动点击“开始监听”或“连接对端”，等待自动连接。地址为 `127.0.0.1` 很正常，它代表当前电脑。两个窗口端口相同，表示它们连接的是同一个通信入口。

### 第三步 核对身份

首次连接会出现身份核验窗口，分别显示本机指纹和对端指纹。正确的对应关系是：

```text
Alice 窗口的 对端指纹  =  Bob 窗口的 本机指纹
Bob 窗口的 对端指纹    =  Alice 窗口的 本机指纹
```

比较完整内容，忽略为便于阅读插入的空格；不要只看最前面几位。两个窗口中分别核对后，各点击一次“已核对，信任此身份”。

为什么要核对：网络中收到一个公钥，并不能直接证明它属于想联系的人。数字签名证明发送方持有相应私钥，首次指纹核验进一步把这个公钥与要联系的人对应起来。

**成功标志：两个窗口都显示“安全连接”。** 如果只确认了一个窗口，另一边仍在等待，连接还没有全部完成。

确认后软件保存信任记录。下次同一身份连接时，可能不再弹出首次核验窗口，这是正常的。若身份发生变化，程序会拒绝；先核实对端是否确实重新生成了身份，不能直接忽略。

## 三 最先完成的五项功能测试

### 测试一 中文文字双向通信

在 Alice 的“通信”页底部输入框里输入：

```text
Bob你好，这是我的第一条加密消息。测试编号：001。
```

点击“发送”。Bob 应显示相同内容。再在 Bob 输入“消息001已收到，我是Bob”，发送给 Alice。

**成功标志：双方都能收到对方的原文，中文没有乱码。**

**原理：发送前自动用 SM4 加密，接收端验证后自动解密。** 你不需要再点一次“解密”。界面显示明文是为了让接收者阅读，不代表网络里直接传输了这段聊天原文。

这项测试证明正常收发可用，但仅凭看到聊天内容，不能证明加密过程正确；后面的密文日志、安全负例和自动测试用来检查其他性质。

### 测试二 图片传输

在 Alice 点击“发送图片”，选择项目 `samples` 文件夹中的 `sample-image.png`。

Bob 应显示接收文件信息、图片预览和一串标为 SM3 的摘要。Alice 在收到文件校验完成回执后，显示“对端已校验接收”。对照两边同一文件的 SM3，内容应一致。

**成功标志：图片预览正常、接收文件存在、两端该文件的摘要相同。** 点击 Bob 的“接收目录”，可以找到实际保存的图片。

**原理：图片被分成多个数据块加密传输；SM3 检查整份文件是否与发送内容一致。** 测试样本较小，进度条可能很快完成。

注意：这里的“文件 SM3”是根据图片内容计算的，与窗口上方根据公钥计算的“身份指纹”用途不同，不能把二者拿来比较。

### 测试三 视频传输

在 Alice 点击“发送视频”，选择 `samples/sample-video.mp4`。这是一个 4 秒的真实 H.264 视频样本。

Bob 收到后，点击“接收目录”，用电脑上的播放器打开接收的 MP4。再比较 Alice、Bob 对该视频显示的 SM3 摘要。

**成功标志：接收完成，视频可以播放，双方该文件摘要相同。**

视频功能是加密视频文件传输，程序不在聊天窗口里播放视频，也不是实时视频通话。需要测试较长传输时，可以发送自己准备的较大视频，单个文件不超过 2 GiB。

### 测试四 反方向文件传输

在 Bob 点击“发送图片”或“发送视频”，选同一个样本发给 Alice。检查 Alice 的接收目录和摘要。

**成功标志：Alice 也能正确接收。** 这样可以证明系统不是只有一个固定发送端、一个固定接收端。

### 测试五 同名文件保护

把同一张图片从 Alice 连续发送给 Bob 两次。打开 Bob 的接收目录。

**成功标志：两份文件都保留，后收到的同名文件追加编号，已有文件没有被覆盖。** 若目录中本来已有同名样本，编号可能继续增加。

## 四 必须了解的安全测试

### 测试六 密文篡改与消息重放

打开“安全实验”页，点击“运行篡改与重放实验”。预期日志出现：

```text
篡改密文：已拒绝
重复记录：已拒绝
```

**篡改**表示原始密文中的某一位被改了，例如恶意修改了转账消息或文件数据。软件通过 HMAC-SM3 检测这种未经授权的修改。

**重放**表示攻击者没有修改某条合法消息，却把旧消息再次发送。例如原本只应执行一次的请求，被原封不动地重复提交。这里通过每个方向严格连续的消息序号检测重复或乱序。

这个按钮会新建一个独立临时测试会话，不是在当前真实连接中插入攻击消息。所以看到拒绝结果后，原来的聊天仍可继续，这是预期设计。

不要把两种测试混为一谈：篡改检测关注内容有没有变化；重放检测关注这条消息是否已经使用过。合法消息即使认证码正确，也不应被无限重复接受。

### 测试七 错误口令

首次设置好身份后，关闭演示，再启动 `start_demo.bat`。这次故意输入错误口令，应显示身份解锁失败。随后输入正确口令，应能正常进入。

**验证点：私钥文件不能用任意密码解开。** 这不会修改原口令，也不会把原身份删除。

### 测试八 首次拒绝信任

若当前已经保存信任记录，先断开连接并等待两端都显示“未连接”。在两个窗口的“会话与身份”页分别清除信任记录，然后关闭并重新启动演示。

再次出现首次核验窗口后，选择一边“拒绝连接”。等待另一边收到断连状态或握手失败提示。

**成功标志：不进入可正常发送应用消息的安全连接状态。** 重新启动并正确核对、确认双方指纹后，可以继续正常演示。

清除信任记录只清除“已经确认过谁”的记录，不会删除自己的身份私钥。不要为了演示而直接修改身份文件内容。

### 测试九 重连生成新会话

在“会话与身份”页记录当前“会话标识”，断开并重新启动演示，再查看新的会话标识。

**预期：同一对端的身份指纹不变，会话标识改变。** 长期身份可以持续使用，每次连接的临时协商和握手记录则重新生成。会话标识本身不是密钥，不需要把它当成密码输入。

### 测试十 一键自动测试

在项目文件夹双击 `run_tests.bat`。出现文字结果窗口后，等待所有测试完成。每个 `ok` 表示对应测试通过，结尾应类似：

```text
Ran 16 tests in ...s

OK
```

运行时间因电脑状态不同而变化。出现 `FAILED` 或 `ERROR` 时表示测试没有全部通过，应保留报错信息再排查。看到“请按任意键继续”是在等待你查看结果，按任意键即可关闭。

自动测试会创建临时身份、临时文件和本机网络连接，不需要你手工操作聊天窗口。测试内容包括：

| 类别 | 检查的行为 |
| --- | --- |
| SM3 | 对已知输入计算的结果是否符合标准向量 |
| SM2 | 正确签名和解密能通过，修改内容、错误密钥或损坏密文被拒绝 |
| 身份文件 | 正确口令能解锁，错误口令不能解锁 |
| 握手 | 临时公钥被替换、角色被反射、随机挑战回显不正确时被拒绝 |
| 加密记录 | 正常双向解密、密文篡改、重复序号、乱序、截断、跨会话记录 |
| TCP 与文件名 | 分片读取、超大帧拒绝、危险文件名拒绝 |
| 实际文件 | 多块二进制、空文件、同名文件、摘要错误和中断清理 |
| 信任记录 | 拒绝首次身份、同名身份的公钥变化时拒绝 |

“全部通过”说明这些指定场景下实现符合预期，不代表对所有网络攻击都做了证明。现场验收还需要自己操作和解释。

## 五 各种密码算法到底负责什么

| 名称 | 通俗解释 | 在本软件中的工作 |
| --- | --- | --- |
| SM4 对称加密 | 加密和解密使用同一份秘密密钥，适合大量数据 | 加密文字、图片和视频的数据块 |
| SM2 非对称加密 | 公钥可以公开，私钥自己持有 | 公钥加密随机挑战，由对端私钥解开 |
| SM2 数字签名 | 用私钥签名，用公钥验证，帮助检查来源与内容 | 签名认证握手消息，绑定协商参数 |
| X25519 密钥协商 | 双方交换公开参数，在各自本地算出同一份秘密 | 每次连接建立共享秘密，不把私钥发给对方 |
| HKDF-SM3 密钥派生 | 从共享秘密中生成用途不同的密钥 | 分别生成两个方向的加密密钥、认证密钥 |
| SM3 摘要 | 把任意长度的数据计算为固定长度摘要，不能当作加密来解回原文 | 文件一致性检查，以及公钥指纹 |
| HMAC-SM3 消息认证 | 根据秘密认证密钥计算认证码，未持有密钥者难以伪造 | 在解密前检查密文记录是否被修改或伪造 |
| scrypt 与 AES-GCM | 根据用户口令保护本地保存的秘密文件 | 加密保存长期身份私钥，不负责主要聊天数据传输 |

可以按这个顺序理解整个流程：

```text
解锁自己的身份
    ↓
交换并验证带 SM2 签名的握手消息
    ↓
X25519 协商共享秘密，HKDF-SM3 派生密钥
    ↓
核对对端身份指纹
    ↓
SM2 加密随机挑战，双方解密回显并确认
    ↓
SM4 加密应用消息，HMAC-SM3 验证记录，序号防重放
    ↓
接收端验证通过后解密显示，文件完成时再检查 SM3
```

代码会先派生候选会话密钥，再等待首次信任核验；只有核验和双方挑战确认全部通过后才允许正常应用通信。

### 为什么既有加密又有认证

加密主要解决“别人能否读懂内容”；认证解决“别人能否修改或伪造内容而不被发现”。仅把数据变成看不懂的形式，并不能自动解决所有篡改问题。

这里先加密再对密文计算认证码。接收端先验认证码，验证通过才解密，因此未经认证的密文不会先进入去填充处理。

### 为什么不能只对文件算 SM3

SM3 不需要秘密密钥，任何人都能计算。如果攻击者同时替换文件和明文传输的摘要，单纯比较摘要无法确认发送者身份。本软件用 HMAC 保护所有传输记录，文件的结束摘要也放在经过认证的加密记录里发送。

### 两边指纹相同或不同要怎么理解

| 比较的两项 | 预期 |
| --- | --- |
| Alice 本机指纹 与 Bob 本机指纹 | 通常不同，因为是两个独立身份 |
| Alice 对端指纹 与 Bob 本机指纹 | 应相同 |
| Bob 对端指纹 与 Alice 本机指纹 | 应相同 |
| 同一文件发送端摘要 与 接收端摘要 | 应相同 |
| 同一对端重连前后的身份指纹 | 身份未重建时应相同 |
| 重连前后的会话标识 | 应改变 |

## 六 文件保存在哪里

从 Alice 发送到 Bob 的文件，保存到项目中的 `runtime/Bob/received/`。反方向则保存到 `runtime/Alice/received/`。直接点击接收方窗口的“接收目录”最方便。

接收完成的文件是已经解密的普通文件，可以打开查看。本软件保护的是通信过程，不会把最终图片或视频继续锁在密文文件里。

`identity.json` 是口令加密的私钥文件；`trusted.json` 是已确认对端的指纹记录。两者职责不同，不要随意混用或交换。源码提交包已经排除正常运行身份和虚拟环境。

## 七 两台电脑怎么连接

先把单机双窗口测试做通，再做双机测试。准备两台能互相访问的电脑，连接到同一局域网，在另一台电脑解压提交包，安装 Python 和依赖。

1. Bob 电脑启动 `start_bob.bat`。首次设置自己的口令。地址填 `0.0.0.0`，端口填 `8765`，点击“开始监听”。
2. 在 Bob 的 Windows 网络连接属性中查看实际 IPv4 地址，例如 `192.168.1.20`。这个地址只是例子，必须换成 Bob 电脑实际地址。
3. Alice 电脑启动 `start_alice.bat`，地址填写 Bob 的实际 IPv4，端口同为 `8765`，点击“连接对端”。
4. 双方通过现场或其他可信方式交叉核对指纹，各自确认后进行文字和文件测试。

`0.0.0.0` 用于 Bob 监听本机各网络接口；它不是 Alice 应填写的目标地址。`127.0.0.1` 只代表自己，也不能用来连接另一台电脑。

两台电脑各自设置的身份保护口令不必相同，因为它只保护各自本地的私钥。双窗口演示共用一次口令输入是启动工具的便利安排，并不是通信协议要求双方共享这个口令。

如果连不上，依次确认：Bob 已监听；目标 IPv4 正确；端口一致；两台电脑网络互通；Python 在当前专用网络中获准接收连接。校园网、访客 Wi-Fi 可能隔离设备，同连一个 Wi-Fi 不一定就能互访。

## 八 常见现象与处理

| 现象 | 先检查什么 |
| --- | --- |
| 不知道默认密码 | 没有预设默认密码，首次设置；已有身份则用当时设置的口令 |
| 一直等待核验 | 是否还有另一个窗口的身份确认没有完成 |
| 没再弹出核验窗口 | 之前已保存同一对端的信任记录，这是正常的 |
| 文字在窗口里是明文 | 接收端已自动解密显示，这是正常的 |
| 视频没有在窗口里播放 | 打开接收目录，用本机播放器播放 |
| 点了图片发送但预览没有出现 | 先确认文件已完成接收；超大图片、损坏图片或不支持格式可能无法预览 |
| 点击安全实验后聊天没断 | 独立测试会话与真实聊天分开，这是正常的 |
| 地址端口输入框变灰 | 当前正监听、连接或已连接；断开后才能修改 |
| 发送按钮不可用 | 尚未完成安全连接，或上一条文字正在提交 |
| 身份改变错误 | 核实对端是否重新生成身份，再通过可信渠道重新核验 |
| 启动窗口报缺少模块 | 双击 install.bat 安装依赖后重新运行 |

本机双窗口演示中关闭 Alice 会同时结束演示进程。需要从头再测时，关闭后重新启动 `start_demo.bat` 即可；保存的身份与已接收文件仍在。

## 九 验收时可以怎样说明

先实际操作，再用自己的话说明下面这段逻辑，不必一开始就背椭圆曲线公式：

“我实现了双端安全通信。双方先用 SM2 签名验证握手，通过可信渠道核对身份指纹；X25519 协商共享秘密，HKDF-SM3 派生密钥。SM2 还用于加密随机挑战，验证解密回显。真正的聊天和媒体内容使用 SM4 加密，每条记录用 HMAC-SM3 认证，连续序号防止重放。文件分块传输，结束后检查大小和 SM3 摘要，通过后才保存为完成文件。”

现场建议按顺序展示：安全连接、双向文字、图片预览、视频文件播放、同名保护、篡改与重放拒绝、自动测试结果。保留自己的实际截图和导出日志，并能在代码中指出 Identity、Handshake、Channel.open 和文件收发的对应位置。

这套方案优先使用 SM2、SM3、SM4，但也使用 X25519 和 AES-GCM，因此不要称为全套国密协议或国密 TLS。
